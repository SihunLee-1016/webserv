# Co-Work Flow

1. Create Issue in ‘Projects’ Tab
2. Create a branch from the `develop` issue 

3. Work on code
4. PR to `develop`
5. Code review
6. Merge

Repeat the above steps.

## Code Convention
Follow the [Google C++ Style Guide](https://google.github.io/styleguide/cppguide.html).

## Code Style 
    - Write both references and pointers attached to the data type.
```cpp
 ⭕️ : int& foo;
 ❌ : int & bar; or int &bar;
 ```
- No parentheses around return
- Return is mandatory for void return functions!
- Use Doxygen (VSCode extension) to write.
- Write comments above the function declaration, not inside the function.
    - When creating a class, write in the order of public, protected, private
- Use enum instead of define
- General variables use snake case
- Member variables use snake case, but add an underscore at the end. (Ex. int this_is_example_)
- All functions use Pascal case. (Ex. void Example_Fun)
```cpp
int num; // General variable snake case

class example {

  int test_; // Member variable snake case + _

  void ExampleFunction(); // Functions are Pascal case

}
```


## Commit Conventions
### Commit Criteria

- Commits are separated according to the commit types below.

### Commit Types

- FEAT: Add or modify features
- ENV: Add or modify the development environment (ESLint changes, Dockerfile changes, etc.)
- FIX: Fix bugs
- DOCS: Modify documentation ([README.md](http://readme.md/) changes, Swagger)
- STYLE: Change code style (prettier, npm run lint, etc.)
- REFACT: Refactor code, same functionality but changed code
- TEST: Add or modify test code
- MERGE: When merging pull requests
- CHORE: Simple typos
- WIP: Work in progress, still in progress

### Commit Examples

```
ex)
FIX: Fixed model validation error
- Added default value for Book title
- Changed minimum length of User intra to 0

ex)
FEAT: Added login feature
- Added auth/api

ex)
TEST: Added bookController test code 
- Added validity test for book title
```

## Branch Convention
- master (main): The latest branch that has been deployed.
- develop: A branch that issues pass through before being merged into master. The results of work done on the issue branch are merged into the develop branch.
- {issue number}-{issue title}: The branch where the work is being done (uses the name automatically generated by GitHub)
